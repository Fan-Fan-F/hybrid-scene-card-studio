# Hybrid Scene Card Studio（2.5D 动态卡牌）

*Turn a single illustration into a draggable 2.5D animated collectible card — with depth, local motion, and the original artwork intact.*

把一张静态插画（或已有分层素材）做成动态收藏卡的 AI Skill：成品可以拖动视角、画面内部有真实的层间景深，特效与衣发等局部有自己的动画，而原画本身不被重绘、不被拉扯变形。本仓库是该 Skill 的 v3 实战修订版完整包，**开源（MIT）**，可直接导入支持 `SKILL.md` 规范的平台使用。

## 它解决什么问题

把一张图「动起来」最省事的做法是整图平移/转动——但那只是图片在动，画面内部没有空间关系，特效不跟随主体、人物轮廓被位移撕扯、脸和敏感部位跟着置换图一起漂移。这类问题在快速制作时很难靠「多看两眼」发现，做完才暴露，返工成本最高。

本 Skill 的定位是把制作过程管住：**每一步该查什么、拿什么证据查、不过关怎么办，都写成可执行的条款、断言和脚本**，问题在进入下一阶段之前就被拦下，而不是等成片出来再猜哪一步错了。它沉淀的是失败机制与检查方法，不是某一张图的答案——每张新图都要重新定性、重新推导规格。

## 核心方法：闸口四件套

1. **先定性，后定案（定性卡）**：开工前先填一张定性卡——主体是谁、什么气质；当前姿态的静态张力在哪；造型里哪些部件可动；原画自带的特效各是什么语义；场景结构与主光源在哪。规格不许凭模板习惯写，只能由定性结论推导。
2. **开工前规格卡**：全项目唯一数据源。允许倾角、必动清单（每项标最小可辨幅度）、应稳定清单、层序合同、特效范围与纯度、环境运动量级等，全部写成可验收的数值或可对图核对的描述，冻结后才许动手；变更走记录、不许口头漂移。
3. **阶段闸口（Gate）**：制作全程分阶段设卡，每道闸口写明「查什么 / 交什么证据 / 不过怎么办」，上一道不过，下一阶段不开工。闸口编号按引入顺序编排，执行顺序以 SKILL.md §4 总览表为准：
   - G0 包完整性 → G0.5 图像定性 → G1 规格卡
   - 第一段（提取与重建）：G2 抠图出口（含主体内部 alpha 完整度内查）、G3 深度真伪、G11 特效原画选材、G4 底板闸口（两段制的门：底板单图先验收，过闸后才许合成）
   - G5 静止空间（拼回母图对照、层序与视差梯度）
   - 第二段（形变与动画）：G6 保护区断言、G7 权重自检、G8 特效出口（轮廓独立性、瞬时元素口径、烘焙表观速度实测、混合模式洗色上限）、G9 环境运动（共场一致）
   - G10 动态验收与交付：实际拖动亲验、证据包齐备、交付文件对账
4. **必交证据图 + 检查脚本**：每道闸口都要交对应的证据（对照图、统计输出、差分图、实测数据条），不能用「看着没问题」结案；能用脚本断言的检查（残渣计数、保护区数值、轮廓重合率等）一律跑脚本，退出码即门禁。

## 交付物长什么样

- 一个可启动、可拖动的**动态网页**（默认用网页实时渲染承载交互与空间；连续衣发、复杂光效等确有收益的素材才用离线烘焙/帧序，按效果逐个选，不强求整卡统一工具）
- **真实多帧预览**（不是单张静帧冒充动效）
- 可编辑的项目文件与独立分层素材，后续可继续修改

单张美图、提示词、制作计划、只转动整张图片，在本 Skill 的口径里都不算完成。

## 检查脚本

均输出 JSON 指标到 stdout，可用退出码作门禁；参数细节见各脚本 `--help`。运行依赖 Python 3 与 `numpy`、`Pillow`（`contour_divergence.py` 另需 `scipy`）。

| 脚本 | 用途（一句话） |
|---|---|
| `audit_skill_links.py` | 审计 SKILL.md 的相对链接是否都指向包内真实存在的文件，防「正文引用了不存在的文档」这类悬空引用。 |
| `alpha_residue_check.py` | 检测抠图残渣：统计远离主体实体、低 alpha 的暗色像素（这类残渣叠在亮背景上会形成一圈灰污），超阈值即拦截。 |
| `contour_divergence.py` | 度量特效轮廓与主体轮廓的重合率，防止特效做成「贴着人物剪影的描边」。 |
| `displacement_guard.py` | 断言置换图在保护区（脸、骨盆等指定矩形）内的数值归零，防止拖动时保护区被视差位移带动。 |
| `plate_diff_check.py` | 对比生成底板与基准图做像素差断言，保证生成补洞「洞外零改动」。 |

## 快速上手

1. 将本仓库作为 Skill 包导入任何支持 `SKILL.md` 规范的平台（如 WorkBuddy、码道 CodeArts 等）。
2. 开工第一件事是跑包完整性自检（闸口 G0），输出零悬空才许开工：

   ```bash
   python scripts/audit_skill_links.py SKILL.md
   # 期望输出包含 "pass": true、"missing_count": 0
   ```

3. 按 SKILL.md 的顺序执行：先填定性卡（模板在 `references/spec-and-generation.md` §0），再冻结规格卡，然后两段制制作、逐闸口交证据。

## 版本说明

当前为 **v3 实战修订版**。v2 相对 v1 的根本变化，是把散文原则落成闸口、证据格式与脚本四件套。v3 在 v2 基础上增补第二轮实战（生图特效原画 + 程序动画化路线）暴露的新失败机制：特效原画选材闸口（G11）、主体内部 alpha 完整度内查与脏点隔离帧定性（G2）、瞬时元素口径先于实现冻结、静图动画化表观速度上限实测（G8）、混合模式洗色的物理上限申报、A/B 对照版单变量纪律，并做了一次全文逻辑顺序与矛盾点排查。
